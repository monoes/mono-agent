# Internationalization (i18n)

Status: **pilot**. This document describes the translation pipeline built
for GitHub issue #26 and its current coverage — a small, working slice of
the CLI and GUI, translated into one pilot locale (Spanish), plus the
mechanism a contributor uses to extend it. It is explicitly **not** a
full translation of the app; see [Scope](#scope) below.

## Framework decisions

**CLI (Go):** a ~150-line internal package, `internal/i18n`, rather than
`golang.org/x/text/message` or another full i18n framework.
[CONTRIBUTING.md](../CONTRIBUTING.md) asks for "no new dependencies
without discussion — prefer the standard library," and the CLI's
translation surface (Cobra `Short`/`Long`/`Example` strings, a handful of
user-facing messages) doesn't need plural rules, gender agreement, or ICU
message formatting — a flat `key -> string` JSON map per locale, embedded
via `go:embed`, covers it with zero new dependencies.

**GUI (React, `wails-app/frontend`):** [`react-i18next`](https://react.i18next.com/)
+ `i18next`. The frontend's `package.json` was already lean (React, Vite,
Vitest, lucide-react — no existing i18n library to lean on), so this pulls
in two new dependencies. `react-i18next` is the de facto standard for
React i18n, is actively maintained, and gives us `useTranslation()` +
interpolation + a `changeLanguage()` runtime switch for free — reimplementing
that as an internal package (as the CLI does) would mean rebuilding
context propagation, interpolation, and re-render-on-language-change from
scratch for no real benefit.

## Scope of this pilot

This is deliberately **not** a full-app translation — see the issue and
the README, which calls this out as "a large but mechanical effort... a
good stamping ground for external contributors." What's actually done:

### CLI — bounded slice

Five command groups' `Short`/`Long`/`Example` strings, in:

- `cmd/monoagentcli/root.go` — root command (`root.short`, `root.long`)
- `cmd/monoagentcli/workflow.go` — `workflow` group + `workflow templates` +
  `workflow search`
- `cmd/monoagentcli/node.go` — `node` group + `node schema`
- `cmd/monoagentcli/connect.go` — `connect` command
- `cmd/monoagentcli/schedule.go` — `schedule` command

All other commands (the other ~25 top-level commands, and every
`workflow`/`node` subcommand not listed above) still print hardcoded
English strings. Extending coverage to another command is mechanical: wrap
the string in `i18n.T("some.key")`, add `"some.key"` to
`internal/i18n/locales/en.json`, and (optionally, for the pilot locale) to
`es.json`.

### GUI — bounded slice

Four components under `wails-app/frontend/src/`:

- `components/Sidebar.jsx` — nav item labels, section headers, profile-menu
  strings
- `components/Toasts.jsx` — error toast text
- `pages/Dashboard.jsx` — page header, stat card labels, the Workflows
  panel
- `pages/Settings.jsx` — page header, Quick Access cards, and the new
  Language section itself

Everything else in the GUI (every other page and component) is still
hardcoded English. `wails-app/frontend/src/services/api.js` and
`components/ResourcePickerField.jsx`/`components/StatusBar.jsx` were
intentionally left untouched in this pass — they were being edited
concurrently for an unrelated fix.

### `ref` manual: explicitly out of scope

`cmd/monoagentcli/ref.go`'s offline manual (the `cliDocs` table — ~150
node-type doc entries plus full command docs) stays **English-only**.
Translating it is disproportionate to a pilot slice (it's the single
largest block of prose in the CLI), and `ref.go` had just been cleaned up
for accuracy in a separate, concurrent change — touching it here would
have conflicted with that work. If `ref` docs are translated in the
future, treat it as its own project: it's an order of magnitude more text
than the rest of the CLI combined.

## Architecture

### CLI: `internal/i18n`

- `locales/<lang>.json` — flat `"key": "value"` maps, embedded via
  `go:embed locales/*.json`. `%s`/`%d`-style verbs are applied with
  `fmt.Sprintf` when `T()` is called with extra args.
- `i18n.T(key, args...)` — looks up `key` in the active locale, falling
  back to English, then to the raw key itself (so a typo or missing
  translation degrades to a visible-but-ugly string, never a panic or
  blank output).
- `i18n.SetLocale(lang)` / `i18n.CurrentLocale()` — set/read the active
  locale (process-global, since the CLI is single-threaded per invocation
  from the user's point of view).
- `i18n.Detect(args)` — resolves the locale from `--lang=xx`/`--lang xx`
  in argv, then the `MONOAGENT_LANG` env var, then `"en"`.

**Why locale detection happens before flag parsing:** Cobra command trees
are built once, in `newRootCmd()`, and `Short`/`Long`/`Example` are plain
string fields set at that construction time — before `cmd.Execute()`
parses `--lang` as a normal flag. So the locale can't be read from a
parsed Cobra flag; `main.go` instead calls `i18n.SetLocale(i18n.Detect(os.Args[1:]))`
*before* calling `newRootCmd()`. The `--lang` persistent flag is still
registered on the root command (so it shows up in `--help` and rejects
unknown flags normally), but its actual effect happens via the pre-scan,
not via the parsed flag value.

### GUI: `react-i18next`

- `src/i18n.js` — initializes `i18next` with the `en`/`es` resource
  bundles, detects the initial language from `localStorage` (key
  `monoagent-lang`) or falls back to `navigator.language`, and persists
  language changes back to `localStorage` on `languageChanged`.
- `src/locales/<lang>.json` — nested JSON, namespaced by
  component/page (`sidebar.*`, `dashboard.*`, `toasts.*`, `settings.*`).
  `react-i18next`'s default namespace and dot-path key resolution handle
  the nesting directly (`t('dashboard.stat.workflows')`).
  Interpolation uses `{{var}}` placeholders (`t('toasts.failed', { op })`).
- `pages/Settings.jsx` has a `LanguageSection` component with a plain
  `<select>` calling `i18n.changeLanguage(lang)` — the only locale-switch
  UI shipped in this pilot.
- `main.jsx` imports `./i18n.js` once at startup, before rendering `<App />`.

## Verification

```bash
# CLI
go build ./... && go vet ./... && go test ./...
go test ./internal/i18n/...              # locale-switch + key-completeness tests

# Manually confirm the pilot locale
./monoagentcli --lang es node --help
MONOAGENT_LANG=es ./monoagentcli schedule --help

# GUI
cd wails-app/frontend
npm run build                            # must succeed; dist/ must contain real content
npm test -- --run                        # must not regress existing tests
```
